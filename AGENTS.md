# AGENTS.md

Guidance for coding agents working in this repository.

## Project Scope

- `src/`: CLI, MCP, scraper, setup, status, and local handoff-index code
- `landing/`: Astro public landing site deployed via GitHub Pages
- `tests/`: scraper, setup, MCP, status, and drift tests
- `docs/`: historical design notes and security documentation

xtctx is CLI/MCP-first. Humans run `xtctx setup` and `xtctx status`; AI
assistants use MCP tools to retrieve recent transcript sessions on demand.
There is no runtime web UI, API server, daemon, watcher, or durable-memory
writeback layer.

## Common Commands

```bash
npm ci
npm --prefix landing ci
npm run verify:release
```

Local handoff setup:

```bash
npx -y xtctx setup
npx -y xtctx status
```

## Configuration Rules

- `.xtctx/config.yaml` is the only project xtctx config file.
- `.xtctx/state/xtctx.db` is rebuildable local cache state and must not be committed.
- Generated managed blocks must be repaired through setup, not edited inside the fences.

## Change Rules

- Use conventional commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`).
- Add or update tests for behavior changes.
- Do not commit local runtime state or generated local wiring (`.xtctx/config.yaml`, `.xtctx/state`, `.claude`, `.codex`, `.cursor`, `.gemini`, `.mcp.json`, `.vscode/mcp.json`, `opencode.json`).

## Release Notes

- Release Please manages versions and changelog.
- Release PRs are auto-merge enabled after required checks pass.
